# Student Performance Predictor

A beginner-friendly full-stack demo using Python, Flask, scikit-learn, SQLite, HTML, CSS and JavaScript.

> Educational demo only: the model is trained on synthetic data and is not validated for real academic decisions.

## Project layout

- `backend/train_model.py`: generates synthetic sample data, trains/evaluates a model, saves `model.joblib`.
- `backend/app.py`: Flask API, validation, prediction, and SQLite prediction history.
- `backend/requirements.txt`: Python dependencies.
- `frontend/`: static website files for Vercel.

## 1. Develop in Google Colab

1. Open https://colab.research.google.com/ and create a notebook.
2. Upload this project ZIP or clone the GitHub repository.
3. Install dependencies: `!pip install -r backend/requirements.txt`
4. Train the model: `!python backend/train_model.py`
5. Test the API in Python using Flask's test client (example in the notebook supplied with this project).
6. Push the project files to GitHub. Include `backend/model.joblib`, which is generated by training.

## 2. Deploy backend to Render

Create a **Web Service** from this GitHub repository:

- Root Directory: `backend`
- Runtime: Python
- Build Command: `pip install -r requirements.txt`
- Start Command: `gunicorn app:app`
- Environment variable (optional): `FRONTEND_ORIGIN=https://YOUR-VERCEL-SITE.vercel.app`

After deployment, check `https://YOUR-RENDER-SERVICE.onrender.com/api/health`.

The model file must exist in the backend directory. Train it before pushing, or include the generated model artifact in the repository.

## 3. Deploy frontend to Vercel

Import the same GitHub repository into Vercel:

- Root Directory: `frontend`
- Framework Preset: Other
- Build Command: leave blank
- Output Directory: leave blank (serve the static files from the root)

Edit `frontend/script.js`: replace `https://YOUR-RENDER-SERVICE.onrender.com` with your actual Render service URL, then commit and push. Vercel will redeploy.

Then set `FRONTEND_ORIGIN` on Render to your actual Vercel origin and redeploy the backend. For local preview, you may temporarily use `FRONTEND_ORIGIN=*`; do not use a wildcard for a production site.

## API endpoints

- `GET /`: basic API information
- `GET /api/health`: service/model health
- `POST /api/predict`: prediction; JSON fields: `study_hours`, `attendance`, `previous_score`, `sleep_hours`
- `GET /api/history`: most recent 20 predictions

## SQLite note

SQLite is used for the history feature. On ephemeral hosting storage, data may be lost when an instance is replaced or redeployed. For persistent deployed history, use a persistent disk or a managed PostgreSQL database. Never store sensitive student information without an appropriate privacy and security plan.
